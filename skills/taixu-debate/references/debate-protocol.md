## Phase 0：证据底座（EvidenceBase）

在 R1 盲立论开始前，西塞罗先向用户展示三档研究预算选项，用户选择后按命题类型调用研究工具，产出共享 EvidencePack 注入所有 R1 task prompt。

### 研究预算选择（西塞罗在开辩前向用户展示）

```
────────────────────────────────────────────────
研究预算选择（请选 1-3，直接回车选默认）

1. 轻量（快）— 2-3 次网络检索，约 30 秒
   适合：辩题背景熟悉，只需补充最新数据

2. 标准（默认）— 多源交叉验证，约 3-5 分钟
   适合：大多数投资和决策辩题

3. 深度（慢但全）— 全渠道并行研究，约 8-15 分钟
   适合：重大仓位决策、理论层认知求真
────────────────────────────────────────────────
```

用户选择后，token 预算上限随档位更新：轻量 4.3×、标准 4.5×、深度 5.0×（相对单一强 prompt 基线）。

### 研究工具路由（按命题类型）

| 命题类型 | 主工具 | 次级工具 | 舆情工具 | Thesis 叠加 |
|---------|--------|---------|---------|------------|
| 投资决策型 | liam-research | — | last30days（强制） | thesis-research（如有档案） |
| 选择决策型 | liam-research | firecrawl-research-index | — | — |
| 认知求真型 | liam-research | firecrawl-research-index | last30days（标准档及以上） | — |

轻量档统一降级为 3 次 WebSearch，不调用上述 skill。

### EvidencePack 结构

产出 EvidencePack 包含：`facts[]`（关键事实）、`data_points[]`（可引用数据）、`disputes[]`（已知争议点）、`sources[]`（来源 URL + 时效）。作为共享底座装入所有 R1 task prompt——五角色看到同一份事实，但解读各自独立，**不破坏盲辩隔离**。

### 混合降级链

- **投资决策型**：EvidencePack 为空（研究失败或超时）→ **hard_stop**，拒绝开辩，西塞罗提示用户补充证据后重试
- **选择决策型 / 认知求真型**：EvidencePack 为空 → **soft_fallback**，继续辩论，报告 frontmatter 标注「⚠️ 无外部证据底座，纯内部知识立论，结论置信度受限」

### 运行目录（run-level 隔离，v0.6.2 新增）

每场辩论开辩时（Phase 0 之前）确定本场运行目录，全程不变：

```
runtime/debate/<date>-<topic_slug>-<run_id>/
```

- `<date>`：开辩日期 YYYY-MM-DD
- `<topic_slug>`：西塞罗开辩时从辩题提炼（英文小写短横线 3-6 词）
- `<run_id>`：开辩时刻 HHmmss；同秒撞名时追加 `-2`、`-3` 后缀

铁律：**同一日期、同一话题的两个并行辩论也不得共用目录**（2026-07-18 事故：同日三场共用日期目录导致 R1/R2 互相覆盖、证据包串台）。本协议下文以 `<run_dir>/` 代指运行目录；R1-R3 发言原文、metadata.json、verifier_r2_lookup.md、evidence_pack.md 一律写入 `<run_dir>/`，禁止写其他目录。

### Phase 0.5：概念对齐（Concept Alignment）（v0.8.0 新增）

在 Phase 0（证据底座）之后、R1 盲立论之前，作为独立子阶段。西塞罗从 EvidencePack 中提取核心概念并统一定义，消除假性分歧。

**为什么不由角色定义**：taixu-debate 是盲辩，角色公开定义概念会泄露立场（奥斯本定义"陪跑"时倾向于"获客乘数"就暴露了发散立场）。概念定义由西塞罗统一定义，保持中性。

**步骤 1 · 西塞罗提取核心概念**（3-5 个）

从辩题 + EvidencePack 中提取多方可能有不同理解的关键术语。提取标准：
- 辩题中出现的、且语义边界模糊的术语
- EvidencePack 的 disputes[] 中涉及的争议性概念
- 跨领域容易产生歧义的术语

**步骤 2 · 西塞罗统一定义**

每个概念给出一句话定义 + 口径边界：
```
概念名：一句话定义（口径边界：包含什么、不包含什么）
```

定义来源优先级：
1. EvidencePack 的事实/数据中提炼（事实层面，中性）
2. EvidencePack 无覆盖时用行业通用定义
3. 以上都无时标注「定义待校验」

**EvidencePack 为空时的降级**（F-8 修复）：概念对齐仍执行，定义来源退到优先级 2（行业通用定义）。所有概念定义标注「⚠️ 无证据底座支撑」。

**LLM 调用规则**（F-6 修复）：主 agent 在 Phase 0 EvidencePack 产出后，直接从 EvidencePack 的 facts[] 和 disputes[] 中提取核心概念并定义，不额外调用 LLM。仅当 EvidencePack 为空（软降级）且辩题含高度领域特异性概念时，才调用 1 次 LLM 辅助定义。

定义要求：操作化、可检验，禁用模糊词（"高效""优质""显著"等）。

**步骤 3 · 产出物与注入**

概念定义表作为 Phase 0.5 独立产出物写入 `<run_dir>/concept_alignment.md`（F-4 修复：不修改 EvidencePack schema），与 EvidencePack 并列注入所有 R1 task prompt。

五角色看到同一份概念定义，角色在立论中须使用统一定义。

**步骤 4 · 事后概念使用检查**（F-1 修复：不要求角色主动声明异议）

角色**不主动声明概念异议**——角色选择补充哪个维度本身就是立场的间接信号，可能破坏盲辩隔离。改为：

- R1 发言中角色须使用西塞罗提供的统一定义进行立论
- **汇总 #1 时**，西塞罗检查每份 R1 发言：角色在实际论证中是否隐含了与统一定义不同的概念理解（表现为论证逻辑隐含了不同的定义口径）
- 如发现偏差，西塞罗在公开记录中标注「⚠️ 概念定义偏差：[角色] 对 [概念] 的实际使用与统一定义不一致」，并在 R2 task prompt 中通知该角色
- 被标注的角色在 R2 中可修正或解释偏差
- 概念使用检查结果记入实录技术记录「概念对齐记录」

### R1 盲立论

**执行方式**: parallel fan-out，5 角色各自独立对辩题立论，互相不可见。

**task prompt 装入**:
- 辩题（命题陈述 + 可选 thesis 上下文摘要）
- 角色自己的 R1 盲立论指引（来自角色快照）
- **Phase 0 产出的 EvidencePack**（v0.6.0 新增，作为共享底座，所有角色收到同一份）
- **Phase 0.5 产出的概念定义表**（v0.8.0 新增，所有角色收到同一份中性定义）

**不装入**: 他方任何信息。

**输出要求**: 按"发言五要素"格式输出。须使用统一定义进行立论。

### 西塞罗汇总 #1

将 5 份 R1 立论合并为公开记录。合并方式：按角色名顺序排列，保留原文，不做摘要。

**发言原文持久化**：汇总时，西塞罗将每份 R1 立论的完整原文写入临时文件 `<run_dir>/R1_<role>.md`。实录生成时从临时文件读取原文，不从会话摘要还原。

**概念使用检查**（v0.8.0 新增）：汇总 #1 时，西塞罗检查每份 R1 发言中角色是否隐含了与统一定义不同的概念理解。如发现偏差，在公开记录中标注「⚠️ 概念定义偏差」，并在 R2 task prompt 中通知该角色。检查结果记入实录技术记录「概念对齐记录」。

### R2 交叉回应

**执行方式**: parallel fan-out，每角色收到公开记录后做交叉回应。

**task prompt 装入**:
- 辩题
- 自己的 R1 立论回放（原文）
- 他方 4 份 R1 立论原文（不做摘要，摘要丢攻击面）
- 角色自己的 R2 交叉回应指引（来自角色快照）

**输出要求**: 按"发言五要素"格式输出。如有反驳，必须含至少 1 个 `[ref:大师名#论点序号]` 引用标记。如无反驳，显式声明沉默。

### 西塞罗汇总 #2

将 5 份 R2 回应合并为公开记录。合并方式同上。

**发言原文持久化**：汇总时，西塞罗将每份 R2 回应的完整原文写入临时文件 `<run_dir>/R2_<role>.md`。

**引用内容校验**：汇总时，西塞罗对 R2 输出中的每个 `[ref:大师名#论点序号]` 标记执行内容校验——找到被引用方 R1 原文，检查引用方表述是否与原文一致。如不一致，在该引用标记旁标注"⚠️ 引用可能不准确"。被错误引用的角色在 R3 task prompt 中收到通知，有权在回应中纠正。校验结果记录在实录的引用校验表中。

**盲区标注**（v0.7.0 新增）：汇总 #2 时，西塞罗扫描 R1+R2 全部发言，标注全场未触及的维度——辩题隐含的利益相关方、用户分层、时序约束、成本结构等被五方集体跳过的角度。只标注「什么维度没被讨论」，不引导、不评价重要性、不站队（权力边界与综合判断一致）。标注注入所有角色的 R3 task prompt，角色自主决定是否响应。时序设计：盲区必须在 R2 后标注而非 R3 后——R4 终辩禁开新战线，R3 是最后一个能承接新维度的发言轮。标注与响应情况记入实录技术记录「盲区标注记录」。

### R3 防御/修正

**执行方式**: parallel fan-out，每角色收到 R2 公开记录后做防御/修正。

**task prompt 装入**:
- 辩题
- 自己的 R1+R2 回放（原文）
- 他方 4 份 R2 回应原文（不做摘要）
- 角色自己的 R3 防御/修正指引（来自角色快照）

**输出要求**: 按"发言五要素"格式输出。如有防御/修正，必须含至少 1 个 `[ref:大师名#论点序号]` 引用标记。如无新内容，显式声明沉默。

### 西塞罗汇总 #3

将 5 份 R3 结辩合并为公开记录。合并方式同上。

**发言原文持久化**：汇总时，西塞罗将每份 R3 结辩的完整原文写入临时文件 `<run_dir>/R3_<role>.md`。

**R3 引用内容校验**：西塞罗对 R3 输出中的引用标记执行内容校验。R3 不再是最后一轮，纠正通道恢复——被错误引用的角色在 R4 task prompt 中收到通知，有权在检验交锋中纠正。

**开放战线清单编译**（v0.7.0 新增）：汇总 #3 时，西塞罗扫描 R3 全部发言，为每个角色编译一份「开放战线清单」。入清单标准（三类）：

1. 他方 R3 中对该角色 R2/R3 立场的**新攻击**（此前轮次未交锋过的）
2. 他方 R3 中提出的**新论证、新设计或修正后立场**，与该角色立场直接冲突或直接相关
3. 他方 R3 中对公开问题（非针对特定角色）的新表态，按核心关切归属到最相关的角色

清单只列「什么议题、谁发起、为什么与你相关」，不预断该如何回应（权力边界与盲区标注一致）。清单写入公开记录，全场可见。

### R4 检验交锋与终辩声明（v0.7.0 新增）

**定位**：交锋链条的合拢轮。任何固定轮次的最后一轮表态都未经检验，这是链条的数学性质——R4 的解法是自带合拢机制：前半段补上对 R3 表态的检验，后半段终辩声明只收拢不新开。终辩的功能是收拢而非新主张，如同法庭最后陈述，不需要再交叉质证。

**默认沉默制**：开放战线清单为空的角色本轮自动沉默，不再 fan-out，公开记录标注「XX R4 沉默——无开放战线」。角色认为清单遗漏了与自己相关的开放战线时可自荐发言，但必须在开头显式指明被遗漏的战线是什么。默认沉默制的含义：**轮次数恒定，发言面动态**——已收敛的角色不制造噪音，有开放战线的角色获得检验通道。这是沉默机制的内生弹性，不是动态轮次判定。

**执行方式**: parallel fan-out，仅开放战线非空的角色。

**task prompt 装入**:
- 辩题
- 自己的 R1+R2+R3 回放（原文）
- 他方 4 份 R3 结辩原文（不做摘要）
- 自己的开放战线清单（西塞罗编制）
- 角色自己的 R4 指引（来自角色快照）

**输出格式**（两段式）：

前半段「**检验交锋**」：对开放战线清单逐条回应——接受、反驳或补充。必须含至少 1 个 `[ref:大师名R3#论点序号]` 引用标记；R4 只允许引用 R3。

后半段「**终辩声明**」三要素：
1. **终态立场**：经全部交锋后的最终立场（一句话）
2. **让步清单**：全场辩论中被说服、显式放弃或降级的论点（可为空）
3. **本轮小结**：≤60 字白话，格式同前

**终辩硬约束**：后半段禁止开新战线——不得提出前三轮未出现过的新论证、新攻击、新数据或新议题。违反时西塞罗标注「⚠️ 终辩开新战线」，该内容不进入三区归纳，仅留在实录。

**R4 引用内容校验**：R4 是最后一轮，无纠正通道。校验结果仅在实录的引用校验表中标注「⚠️ 引用可能不准确」，不影响辩论进程。

**全员沉默**：如汇总 #3 后所有角色的开放战线清单均为空，跳过 R4 直接进入报告生成，报告标注「R4 未举行——R3 后无开放战线，交锋已穷尽」。

**临时文件元数据**：全部轮次结束后，西塞罗将辩论元数据（辩题、topic_slug、日期、run_id、角色、执行模式、token 消耗）写入 `<run_dir>/metadata.json`；交付物归档后回写 archived_deliverables 指针。topic_slug 由西塞罗开辩时从辩题提炼（英文小写短横线 3-6 词，如 ai-semiconductor-capex-bubble）。

**概念定义偏差事后校验**（v0.8.0 新增，F-3 修复）：R4 结束后、报告生成前，西塞罗回顾 R1-R4 全部发言，检查是否有角色在实际论证中使用了与统一定义不同的概念理解（表现为论证逻辑隐含了不同的定义口径）。如有，在技术记录中标注「概念定义偏差」并说明影响范围——该偏差是否影响了分歧/共识的判定。

**临时文件清理**：交付物归档后，`<run_dir>/` 仅保留过程文件（R1-R4 发言原文、metadata.json、verifier_r2_lookup.md、evidence_pack.md、concept_alignment.md），交付物正本与双轨版本一律不留临时区。西塞罗提示用户"过程文件保留于 <run_dir>/，确认后可手动清理"。

### 报告生成（双产出 + 自动润色）

西塞罗基于 R1+R2+R3+R4 全部记录生成**两份产出物**。实录中的发言内容从临时文件 `<run_dir>/` 读取原文，不从会话摘要还原：

1. **摘要版裁决书**：辩论精华 + 三区（共识/分歧/未决）+ 综合判断 + 结论产出（按命题类型分流），正文 ≤1200 字，阅读 ≤4 min。格式见 [templates/report-template.md](../templates/report-template.md) 的"报告结构"节。
2. **全程实录汇总稿**：辩论赛标准格式，含四轮各角色发言全文 + 西塞罗注记 + 裁决书内嵌 + 技术记录。结构见 [templates/report-template.md](../templates/report-template.md) 的"全程实录结构"节。

摘要版裁决书必须**面向人读**：禁止术语黑话，用自然段落不用标签式列表，普通人能直接读懂。鼓励类比和具象化表达，允许结构化表格。详见 [templates/report-template.md](../templates/report-template.md) 的「面向人读（硬约束）」节。

两份文档生成后，主 agent **自动调用 liam-polish** skill 对两份产出物做润色（消除 AI 味与翻译腔），无需用户确认。润色流程见 [templates/report-template.md](../templates/report-template.md) 的「自动润色流程」节。

**数据可靠性审查**（全程实录专属）：报告生成前，西塞罗提取辩论中引用的关键外部数据，标注原始来源、口径、可靠度。西塞罗尝试搜索外部数据后若返回空结果或超时，自动降级为标注引用来源但标注口径未核实。如辩论未引用外部数据，标注「本场无外部数据引用」后跳过。详见 [templates/report-template.md](../templates/report-template.md) 的「全程实录结构」第 6 项。

降级路径下（无 workflow.js），主 agent 同样执行双产出 + 自动润色。

**交付物归档（硬约束）**：双产出 + 自动润色完成后，西塞罗以润色稿为正本，将两份交付物归档至 `docs/taixu-debate-reports/`（与 docs/hegel-reports 等五原子 skill 报告目录惯例一致），命名 `<topic_slug>-taixu-debate-report-<date>.md` 与 `<topic_slug>-taixu-debate-transcript-<date>.md`。归档只留润色后正本，不留 -原文/-润色稿 双轨。

## 发言五要素

每轮发言（R1/R2/R3）必须包含以下五个要素（R4 采用两段式格式，见「R4 检验交锋与终辩声明」节）：

1. **立场**: 对辩题的核心判断（支持/反对/部分支持/悬置）
2. **核心论据**: 支撑立场的 1-3 条关键论据
3. **对他方论点的反驳**（R1 无此项）: 引用他方具体论点并反驳，格式 `[ref:大师名#论点序号]`
4. **沉默声明**: 如无反驳/防御/修正内容，显式声明沉默（"XX沉默——理由"，XX 为大师名）
5. **本轮一句话小结**（v0.6.0 新增）: ≤60 字白话收口，说明"我这一轮坚持/松动/转向了什么，因为什么"。要求：不用术语、不用角色名、不用标签，普通读者能直接读懂。

R1 的第 3 项替换为"被攻击面预判"：预判自己的立论最可能被他方从哪个角度攻击。

### 本轮小结格式

```
**本轮小结**：我这一轮坚持了 [立场]，因为 [一句话理由]。
```

或（立场松动时）：

```
**本轮小结**：我这一轮从 [旧立场] 松向 [新立场]，因为 [一句话理由]。
```

小结是强制项，不可省略。实录和裁决书均保留此小结。

## 沉默权

沉默是合法的发言，不是放弃。

- R2 沉默 = 认为他方立论已覆盖自己的关切，无反驳可补
- R3 沉默 = 认为他方 R2 反驳有效或自身立场无需修正
- R4 沉默 = 开放战线清单为空（制度性沉默，非质量信号，不计入交锋充分度分母）

角色快照中定义了各角色的沉默条件和沉默声明格式。

## 引用规则与机械校验

### 引用标记约定

```
[ref:大师名#论点序号]
```

- 大师名: 奥斯本 / 黑格尔 / 贝叶斯 / 费曼 / 德博诺（与机器标识 divergent / convergent / verifier / auditor / integrator 一一对应）
- 论点序号: 被引用方在该轮发言中的论点编号（从 1 开始）

示例: `[ref:贝叶斯#2]` 表示引用贝叶斯第 2 个论点。

### 机械校验规则

报告生成前，西塞罗对 R2、R3、R4 的每份输出执行以下校验：

1. **非沉默输出必须含引用**: 如输出未声明沉默，则必须含至少 1 个 `[ref:...]` 标记。无引用的非沉默输出 = 校验失败。
2. **引用目标必须存在**: `[ref:大师名#论点序号]` 中的大师名必须是 5 位大师之一，论点序号必须在该角色对应轮次的输出中存在。
3. **引用方向必须正确**: R2 只能引用 R1 的论点；R3 只能引用 R2 的论点；R4 只能引用 R3 的论点。

校验失败的输出退回该角色重发一次。二次失败则强制标记为沉默。

### 引用内容校验（v0.3.0 新增）

在机械校验（格式）之外，西塞罗在汇总 #2 时对 R2 输出执行引用内容校验：

1. **校验方式**：对每个 `[ref:大师名#论点序号]` 标记，找到被引用方原文，检查引用方表述是否与原文一致
2. **不一致处理**：在该引用标记旁标注"⚠️ 引用可能不准确"
3. **通知机制**：被错误引用的角色在下一轮（R3 或 R4）task prompt 中收到通知，有权在回应中纠正
4. **R4 校验**：R4 是最后一轮，无纠正通道。校验结果仅在实录的引用校验表中标注，不影响辩论进程
5. **校验记录**：所有校验结果记录在实录的引用校验表中（含内容校验列）

## 兜底分支

### 单角色沉默

角色在任何轮次声明沉默后，后续轮次自动跳过该角色（不再 fan-out）。该角色的沉默声明仍计入公开记录。

### 全员沉默（R2 或 R3）

如 R2 或 R3 全部 5 个角色均声明沉默：

- R2 全员沉默 → 跳过 R3 与 R4，直接进入报告生成
- R3 全员沉默 → 跳过 R4，直接进入报告生成
- R4 不举行还有一种情形：汇总 #3 后开放战线全空（见「R4 检验交锋与终辩声明」节）

报告需标注"R2/R3 全员沉默——分歧已在 R1 充分暴露，无交叉反驳空间"。

### 部分角色沉默

如 R2 或 R3 有 1-4 个角色沉默，其余角色正常输出。沉默角色在后续轮次自动跳过。

## token 硬上限（R8）

### 基线定义

**单一强 prompt 基线** = 同一辩题用单个 agent 一次性分析（无辩论结构）的 token 消耗。在辩论开始前由西塞罗先执行一次基线测量（或使用预设的基线值）。

### 硬上限

单场全流程 token 消耗 ≤ 4.5× 基线（v0.7.0 起；随研究预算档位浮动，见 Phase 0）。

### 计数口径

- 输入 token + 输出 token 均计入
- 4 轮 fan-out × 5 角色 = 最多 20 次 subagent 调用（R4 默认沉默制下，实际调用数 = 开放战线非空的角色数，通常 <5）
- 每次调用的 task prompt（辩题 + 上下文回放）+ 角色输出均计入
- 西塞罗汇总操作不计入（无 LLM 调用，仅字符串拼接）

### 超限硬终止

如运行时可统计 token 用量（如 API 响应 metadata），实时监控累计 token。超限时：

- 如当前轮次未完成 → 终止当前轮次，已有输出保留，缺失角色标记为"token 超限终止"
- 如当前轮次已完成 → 不进入下一轮次，直接进入报告生成

如运行时不可统计 token 用量，降级为代理指标：

- 轮次预算上限: 4 轮（R1+R2+R3+R4）
- 单轮单角色输出上限: 800 字
- 超限处理同上

降级口径在 U4 实现时验证后锁定写入本文档。

## 降级路径执行方式

无 workflow.js 环境时，主 agent 按本协议用 Agent 工具 dispatch 自定义 subagent：

0.5. **概念对齐**（v0.8.0 新增）：主 agent 在 Phase 0 EvidencePack 产出后、dispatch R1 subagent 前，从 EvidencePack 的 facts[] 和 disputes[] 中提取核心概念并定义，将概念定义表写入 `<run_dir>/concept_alignment.md`。仅当 EvidencePack 为空且辩题含高度领域特异性概念时，才调用 1 次 LLM 辅助定义。概念定义表与 EvidencePack 一起装入每个 R1 subagent 的 task prompt
1. **R1**: 一条消息中并行 dispatch 5 个 `debate-{role}` subagent，task prompt 装入辩题 + 角色 R1 指引 + EvidencePack + 概念定义表
2. **汇总 #1**: 主 agent 收集 5 份输出，按角色名顺序拼接为公开记录。同时将每份输出写入 `<run_dir>/R1_<role>.md`
3. **R2**: 一条消息中并行 dispatch 5 个 subagent（沉默角色跳过），task prompt 装入辩题 + 自己 R1 回放 + 他方 R1 原文 + 角色 R2 指引
4. **汇总 #2**: 同上，将每份输出写入 `<run_dir>/R2_<role>.md`。同时执行引用内容校验，被错误引用角色在 R3 task prompt 中收到通知；并标注全场盲区（只标注不引导），注入 R3 task prompt
5. **R3**: 一条消息中并行 dispatch 5 个 subagent（沉默角色跳过），task prompt 装入辩题 + 自己 R1+R2 回放 + 他方 R2 原文 + 盲区标注 + 角色 R3 指引。如汇总 #2 发现引用不准确，在 task prompt 中通知被错误引用角色
6. **汇总 #3**: 将每份 R3 输出写入 `<run_dir>/R3_<role>.md`；执行引用内容校验（被错误引用角色在 R4 task prompt 中收到通知）；编译各角色开放战线清单
7. **R4**: 一条消息中并行 dispatch 开放战线非空的 subagent（清单为空的角色自动沉默，不 dispatch），task prompt 装入辩题 + 自己 R1+R2+R3 回放 + 他方 R3 原文 + 开放战线清单 + 角色 R4 指引
8. **R4 持久化**: 将每份 R4 输出写入 `<run_dir>/R4_<role>.md`，写入 `metadata.json`
9. **报告生成**: 主 agent 从临时文件读取发言原文，基于 R1+R2+R3+R4 全部记录按 [report-template.md](../templates/report-template.md) 生成报告。实录生成后提示用户可手动清理临时文件

引用机械校验由主 agent 在报告生成前执行。

## 贝叶斯二次检索权（v0.6.0）

贝叶斯在 R2 阶段，如发现 Phase 0 的 EvidencePack 未覆盖其需要验证的预测，可发起一次轻量补充检索（≤3 次 WebSearch）。

规则：
1. 仅贝叶斯（verifier）享有此权；其他角色不可调用
2. 检索结果写入 `<run_dir>/verifier_r2_lookup.md`
3. 西塞罗将 `verifier_r2_lookup.md` 追加到 R2 公开记录尾部，标注「贝叶斯补充检索」
4. 所有角色在 R3 task prompt 中收到此补充（信息对称，不破坏公平）
5. 贝叶斯须在 R2 发言中显式声明「触发二次检索，原因: <X>」
6. 二次检索 token 计入 Phase 3（CrossResponse）预算，不单独计算
