# 太虚五转 Blind A/B Review Prompt Template

> **版本**: v1.0 | **日期**: 2026-06-30
> **用途**: 异构模型盲审——对两份隐去版本的五转产出报告独立打分

---

## 使用说明

1. 将两份五转综合产出报告分别标记为 **报告 A** 和 **报告 B**（随机分配，隐去版本号和时间戳）
2. 将本模板 + 报告 A + 报告 B + 13 维度 rubric 一起发送给审查模型
3. 审查模型输出 JSON 格式评分结果
4. 使用 `scripts/taixu-blind-review.py` 汇总多模型结果

---

## Prompt 模板

```
你是一名独立的太虚五转方法论评估审查员。你的任务是对比评估两份五转产出报告（标记为 A 和 B），按 13 个维度打分。

## 评分规则

### 打分标准
- 每个维度 0-10 分，分数必须是整数
- 参照下方 13 维度 rubric 的锚点定义打分
- 打分基于产出物中可观察的证据，不做主观推测
- 若某维度的证据不足，给 3 分并标注 "evidence_insufficient"

### 13 维度定义速查

**系统级（D1-D8）:**
- D1 方法论覆盖深度（权重10）: 六要素（第一性原理/贝叶斯公式/剃刀法则/有界贝叶斯/相变识别/时间最优）的实现深度
- D2 管线编排完整性（权重10）: 五转串联完整度+信号传递+是否有降级
- D3 评估严谨度（权重10）: 有无回归语料库/blind A/B/量化指标追踪
- D4 问题路由准确率（权重5）: problem_type 三信号路由的判定准确性
- D5 上下文纪律（权重5）: SKILL.md token 控制+触发词精度
- D6 可移植性与入门体验（权重5）: 跨平台同步+quickstart+新用户可理解度
- D7 运营闭环（权重5）: 典型值校准+漂移检测+SkillOps报告
- D8 本地可靠性（权重5）: 脚本测试覆盖+CI集成+降级模式

**过程级（D9-D13）:**
- D9 发散质量（权重12）: 想法数量+SCAMPER覆盖+视角数+组合衍生
- D10 收敛稳定性（权重12）: 收敛状态+压缩率+盲区识别+边界漂移检查
- D11 验证有效度（权重10）: 预测数量+验证通过率+异构模型+盲区发现
- D12 审查检出力（权重8）: 合规率+问题分级+反例验证+修复建议
- D13 归真价值找回率（权重8）: 存活论证+策略覆盖+价值扫描+打捞元素

### 锚点速查（0-10 → 质量等级映射）
- 0-2: 严重缺失（维度基本不存在）
- 3-4: 有但不足（有实现但效果差/未度量）
- 5-6: 及格（基本要求满足，有度量）
- 7-8: 良好（超出基本要求，有量化追踪）
- 9-10: 优秀（行业领先，有 A/B 对比数据）

## 加权分计算规则

- 系统级加权分 = Σ(D_i × weight_i / 10)，i=1..8
- 过程级加权分 = Σ(D_i × weight_i / 10)，i=9..13
- 总分 = 系统级加权分 + 过程级加权分
- 权重: D1=10, D2=10, D3=10, D4=5, D5=5, D6=5, D7=5, D8=5, D9=12, D10=12, D11=10, D12=8, D13=8

## 注意事项

1. 你看到的两份报告版本信息已隐去，请基于内容质量而非版本偏好打分
2. framework_gaps 是元指标，用于监控六要素框架的完整性。请认真思考："这个产出是否反映出某个方法论能力缺失？"——例如：
   - "缺少对多利益相关方博弈的分析能力"
   - "时间维度分析不足，无法处理时变系统"
   - "缺乏对反面证据的系统性搜索"
3. 若 framework_gaps 为空数组 []，表示你认为框架完整
4. dimension_notes 中每条简述差异，帮助理解打分逻辑
```

## 执行协议

### 1. 准备阶段

```bash
# 1. 收集 1.0 基线产出物和 2.0 升级后产出物
# 2. 随机分配 A/B 标签（用 Python random.shuffle 确保）
# 3. 记录映射关系到 mapping.json（仅仲裁者持有）
```

### 2. 分发阶段

对每个回归语料库的题目：
- 将本 prompt 模板 + 报告 A + 报告 B 发送给 3 个异构模型
- 模型列表（从 .env 读取）：
  - **审查员 A**: Claude（当前会话模型，测"自审能力"）
  - **审查员 B**: Gemini（`GOOGLE_API_KEY` + `gemini-2.5-flash`）
  - **审查员 C**: Qwen（`DASHSCOPE_API_KEY` + `qwen3.8-max`，统一 llm_client）

### 3. 收集阶段

每个审查模型返回一份 JSON，保存为：
```
evals/results/{case_id}/{reviewer_id}.json
```

### 4. 汇总阶段

```bash
python scripts/taixu-blind-review.py --results-dir .agents/skills/taixu-pipeline/evals/results/
```

输出：
- `evals/results/summary-{date}.md` — 汇总报告
- `evals/results/summary-{date}.json` — 机器可读汇总

### 5. 仲裁规则

- 3 个审查模型对某维度的打分方差 > 2 → 标记为 `NEEDS_HUMAN_REVIEW`
- 投票结果 2:1 → 少数方被记录但采纳多数方
- 投票结果 1:1:1 → 标记为 `TIE`，触发人工裁决
- 投资决策类题目 → 无论方差大小，必须人工复核
- framework_gaps 中同一缺失被 ≥2 个审查者提及 → 记入 BACKLOG
