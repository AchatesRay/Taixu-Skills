## 元指标：框架有效性监控

**定义**：六要素框架作为假设接受，不独立验证其完整性。通过盲审开放性问题监控盲区。

**操作**：在盲审 prompt 末尾附加开放性问题——"这个产出是否反映出某个方法论能力缺失？"
- 若 3 个异构模型审查者中 ≥2 个指出同一个缺失能力 → 记入 BACKLOG
- 不计入 100 分总分，作为"框架健康度"信号跟踪
- 阈值：同一缺失能力被 ≥2 个审查者提及 → 触发六要素框架审查

## Tier 1: 系统级指标（50 分）

### D1. 方法论覆盖深度（权重 10）

**定义**：六要素在 skill 中的实现深度（有无、有无量化追踪、效果是否度量）

| 分数 | 标准 |
|------|------|
| 0-2 | ≤2 要素有实现，无量化追踪 |
| 3-4 | 3-4 要素有实现，但效果未度量 |
| 5-6 | 5 要素有实现，≥2 有量化追踪 |
| 7-8 | 6 要素全部实现，≥3 有效果度量 |
| 9-10 | 6 要素全部实现且全部有效果度量，有 A/B 对比数据 |

**如何度量**：
- 逐要素检查：第一性原理→osborn P0.2 是否存在；贝叶斯公式→bayes B1/B2 是否运行；剃刀法则→hegel rigor gate 第 6 维 simplicity 探针（0-2 分）；有界贝叶斯→bayes 是否有置信度区间；相变识别→check-convergence.py detect_phase_transitions() 是否输出相变事件；时间最优→是否有 time_budget 配置
- 量化追踪：每个要素是否有可提取的度量值（如 rigor PASS 率含 simplicity 维度、验证通过率、相变检测次数、收敛轮次）
- 6 要素全部实现且 ≥3 有效果度量 → 7-8 分

---

### D2. 管线编排完整性（权重 10）

**定义**：五转串联的完整度和信号传递质量

| 分数 | 标准 |
|------|------|
| 0-2 | ≤2 转可运行，无 CHECKPOINT |
| 3-4 | 5 转可运行，但信号传递断裂（上转输出不传给下转） |
| 5-6 | 5 转完整串联，CHECKPOINT 有记录，但 ≥1 转降级运行 |
| 7-8 | 5 转完整串联，无降级，CHECKPOINT 信号完整传递 |
| 9-10 | + 异常处理（某转失败时 pipeline 有降级策略）+ 可观测性面板 |

**如何度量**：
- 检查 taixu-pipeline composition 中 5 个 step 是否全部有 checkpoint: true
- 检查各转 report 的 YAML frontmatter 是否有 pipeline_step 和 next_step 字段
- 降级检测：bayes B2 是否从异构降级为单模型；hegel 是否 standalone（跳过 S3-S5）；feynman 是否自我审查（非 subAgent 独立）

---

### D3. 评估严谨度（权重 10）

**定义**：回归语料库、blind A/B、量化指标追踪的完备程度

| 分数 | 标准 |
|------|------|
| 0-2 | 无回归语料库，无 blind A/B |
| 3-4 | 有 evals 文件但 <10 题，无 blind A/B |
| 5-6 | 回归语料库 ≥20 题，有 blind A/B 协议但未执行 |
| 7-8 | 回归语料库 ≥50 题，blind A/B 已执行 ≥1 轮，0 退步 |
| 9-10 | 回归语料库 ≥50 题，blind A/B 胜率 ≥70%，量化指标 ≥10 个且有趋势追踪 |

**如何度量**：
- 统计 evals 目录下的 case 数量
- 检查 blind A/B 报告是否存在
- 统计量化指标数量（precision、recall、收敛率、检出率等）

---

### D4. 问题路由准确率（权重 5）

**定义**：problem_type 三信号路由的判定准确性

| 分数 | 标准 |
|------|------|
| 0-2 | 无 problem_type 路由，或路由从未被触发 |
| 3-4 | 有路由机制但准确率未度量 |
| 5-6 | 路由准确率 ≥60%（基于 ≥20 次使用数据） |
| 7-8 | 路由准确率 ≥80%，lens→type 映射可信 |
| 9-10 | 路由准确率 ≥90%，有异常路由自动告警 |

**如何度量**：
- 检查 osborn P0.1 三信号分类是否存在（complexity/uncertainty/novelty）
- 统计 problem_type 判定记录数量
- 人工验证：抽取 ≥10 次判定，检查 problem_type 与实际分析结果是否吻合

---

### D5. 上下文纪律（权重 5）

**定义**：各 skill 的 token 预算控制

| 分数 | 标准 |
|------|------|
| 0-2 | 任一 skill SKILL.md >5000 tokens，无预算约束 |
| 3-4 | 有预算声明但未执行，或 >1 个 skill 超预算 |
| 5-6 | 全部 skill ≤4000 tokens，有触发词 blind test |
| 7-8 | 全部 skill ≤3000 tokens，触发词 precision ≥90% |
| 9-10 | 全部 skill ≤3000 tokens，触发词 precision ≥95%，有 token 趋势追踪 |

**如何度量**：
- `wc -m` 各 skill SKILL.md 字符数，估算 tokens = chars / 3
- 检查是否有 token 预算声明（SKILL.md frontmatter 或 references/）
- 触发词 blind test：给 10 个非触发短语 + 10 个触发短语，检查 skill 是否正确区分

### D6. 可移植性与入门体验（权重 5）

**定义**：跨平台同步一致性 + 独立可用性 + 新用户可理解度

| 分数 | 标准 |
|------|------|
| 0-2 | 无同步机制，无 README |
| 3-4 | 有 skill-sync + 有版本演进记录，但无 quickstart |
| 5-6 | + 同步一致性 ≥90% + 有 README |
| 7-8 | + 同步一致性 ≥95% + quickstart + 新用户 5 分钟能上手 |
| 9-10 | + 同步一致性 100% + 新用户盲测通过率 ≥80% |

**如何度量**：
- 检查 skill-sync 是否存在且可运行
- 检查 README 或 quickstart 文档是否存在
- 同步一致性：对比 .agents/skills/ 与 .qoder/skills/ + .claude/skills/ 的 checksum 差异
- 新用户盲测：给 3 个新人看 quickstart，能否 5 分钟内理解五转流程

### D7. 运营闭环（权重 5）

**定义**：典型值校准、漂移检测、SkillOps 报告

| 分数 | 标准 |
|------|------|
| 0-2 | 无典型值校准，无漂移检测 |
| 3-4 | 有时间基准值但为估计值（未实战校准） |

**如何度量**：
- 检查 time_baselines 是否标注"校准值"还是"估计值"
- 检查是否有漂移检测脚本或规则
- 检查是否有 SkillOps 报告（月度或周度）

### D8. 本地可靠性（权重 5）

**定义**：脚本测试覆盖、CI 集成、降级模式健壮性

| 分数 | 标准 |
|------|------|
| 0-2 | 无测试，无 CI，降级模式未定义 |

| 9-10 | 脚本测试覆盖 ≥90%，CI 绿灯，降级模式有回归测试 |

**如何度量**：
- 统计各 skill 下的脚本数 vs 有测试的脚本数
- 检查 GitHub Actions 或 Makefile 是否有 evals 自动执行
- 检查降级模式（如 bayes B2 降级、hegel standalone）是否有测试用例

## Tier 2: 过程级指标（50 分）

### D9. 发散质量（权重 12）

**定义**：osborn 阶段的想法数量、维度覆盖、SCAMPER 完备性

| 分数 | 标准 |
|------|------|
| 0-2 | <10 个想法，无 SCAMPER |
| 3-4 | 10-25 个想法，SCAMPER ≤3/7 |
| 5-6 | 25-50 个想法，SCAMPER ≥5/7，≥3 视角 |
| 7-8 | 50-100 个想法，SCAMPER 7/7，≥4 视角，有组合衍生 |
| 9-10 | >100 个想法，SCAMPER 7/7，≥4 视角，组合衍生 ≥5，有想法去重机制 |

**如何度量**：
- 读取 osborn idea-pool 的 YAML frontmatter: `total_ideas`
- 统计 P2a SCAMPER 七字母覆盖：S/C/A/M/P/E/R
- 统计 P2b 视角数：用户/技术/竞争者/边缘
- 检查是否有组合衍生（`[组合: #X+#Y]` 标注）
- 重复率：hegel 识别的重复想法数 / total_ideas

### D10. 收敛稳定性（权重 12）

**定义**：hegel 阶段的收敛状态、压缩率、盲区识别

| 分数 | 标准 |
|------|------|
| 0-2 | 未收敛（truncated/diverged），无盲区识别 |
| 3-4 | 收敛但 >3 轮，或无盲区输出 |
| 5-6 | 1-3 轮收敛，压缩率 ≥70%，有盲区列表 |
| 7-8 | 1 轮收敛，压缩率 ≥80%，≥3 盲区，有边界漂移检查 |
| 9-10 | 1 轮收敛，压缩率 ≥90%，≥5 盲区，有边界漂移检查 + 选项对比 |

**如何度量**：
- 读取 hegel report 的 `status` 字段（converged/truncated/diverged）
- 压缩率 = 1 - (提取断言数 / 输入想法数)
- 盲区数量：读取 hegel report 的盲区列表
- 检查是否有边界漂移检查章节
- 检查是否有候选方案对比（Option A/B/C）

### D11. 验证有效度（权重 10）

**定义**：bayes 阶段的预测验证质量、盲区发现率

| 分数 | 标准 |
|------|------|
| 0-2 | 未运行 bayes，或无预测验证 |
| 3-4 | B1 硬验证但 <3 条预测，无 B2 软验证 |
| 5-6 | B1 验证 ≥5 条，B2 软验证运行（可为降级模式），盲区 ≥2 |
| 7-8 | B1 验证 ≥8 条，B2 异构模型验证，盲区 ≥3，有预测汇总表 |
| 9-10 | B1 验证 ≥10 条，B2 异构模型一致率 ≥80%，盲区 ≥5，有置信度分布 |

**如何度量**：
- 读取 bayes report 的预测数量和验证结果（VERIFIED/REFUTED/EPISTEMIC）
- 检查 B2 模式：L1 降级（单模型）/ L1.5 WebSearch 降级 / L2 异构（双模型）
- L1.5 WebSearch 降级计为“B2 软验证运行（降级模式）”，满足 5-6 分要求
- 统计盲区数量和严重度分布
- 检查是否有验证汇总表

### D12. 审查检出力（权重 8）

**定义**：feynman 阶段的问题检出率和合规率

| 分数 | 标准 |
|------|------|
| 0-2 | 未运行 feynman，或合规率 ≤1/6 |
| 3-4 | 合规率 2-3/6，有问题列表但无修复建议 |
| 5-6 | 合规率 3-4/6，有问题列表 + 修复建议，有反例验证 |
| 7-8 | 合规率 4-5/6，有反例验证 + 阻塞/非阻塞分级 |
| 9-10 | 合规率 ≥5/6，误报率 <10%，修复建议可执行率 ≥80% |

**如何度量**：
- 读取 feynman report 的合规率（x/6）
- 统计问题数和分级（❌阻塞 / ⚠️非阻塞）
- 检查是否有反例验证（"步骤→预期→结果"格式）
- 检查是否有修复建议

### D13. 归真价值找回率（权重 8）

**定义**：debono 阶段的存活论证质量和价值打捞

| 分数 | 标准 |
|------|------|
| 0-2 | 未运行 debono，或无存活论证 |
| 3-4 | 有存活论证但无四维价值扫描 |

**如何度量**：

- 检查是否有打捞价值元素列表
- 检查是否有与 feynman ❌ 的响应表

## 评分协议

### 打分流程
1. 逐维度阅读产出物，按 rubric 锚点打分（0-10）
2. 乘以权重 / 10 得到加权分
3. 汇总系统级（50）+ 过程级（50）= 总分（100）
4. 输出区间分数（如 43-46）而非精确值

### 异构盲审协议
1. **审查员 A**：Claude（主模型，测"自审能力"）
2. **审查员 B**：Gemini（异构训练数据）
3. **审查员 C**：Qwen（异构训练数据，与 Claude 差异最大）
4. **取中位数** → 方差 >2 触发人工裁决
5. **人工盲审**：仅 AI 分歧最大的题（方差 >2）或关键题（投资决策类）

### 盲审 prompt 结构化格式
```
输入：
  - 报告 A（隐去版本）
  - 报告 B（隐去版本）
  - 13 维度 rubric（本文档）

输出（JSON）：
  {
    "scores_A": { "D1": x, "D2": x, ... "D13": x },
    "scores_B": { "D1": x, "D2": x, ... "D13": x },
    "winner": "A" | "B" | "tie",
    "framework_gaps": ["缺失能力描述1", ...]
  }
```

### 分数表述规范
- **基线分数**：用区间（如 43-46）
- **目标分数**：用区间（如 66-74）
- **ROI**：用区间百分比（如 +43% 到 +57%）
- 禁止使用小数点精度（如 46.4），因数学假精度无实际意义

## 适用边界

本 rubric 不适用于以下场景：
- **非太虚五转管线产出**：本 rubric 13 维度与五转方法论六要素绑定，单独评估 osborn/hegel/bayes/feynman/debono 任一转的产出不适用（需用各转独立的评估标准）
- **手动五转（非自动编排）**：D2 管线编排完整性维度依赖 CHECKPOINT 信号传递，手动串联无 CHECKPOINT 时不适用 D2 评分
- **跨 pipeline 版本比较**：v1.0-v1.1 与 v1.2+ 口径不可比（见 Breaking Change），跨版本比较必须使用同尺盲评协议
- **非投资决策类问题**：D9 发散质量/D10 收敛稳定性的锚点（如 ≥50 个想法、压缩率 ≥80%）针对复杂决策问题校准，简单问题（如单一技术选型）不适用
- **单模型环境**：D3 评估严谨度要求异构模型盲审，单模型环境下 B2 软验证强制降级，D3 上限为 5-6 分
