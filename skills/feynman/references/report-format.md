## 判定阈值与严重度分级

- 6/6 ✅：通过，无需改动
- 有 ⚠️ 无 ❌：通过，非阻塞问题（建议改进，列出建议但不阻断）
- 有 ❌：不通过，阻塞问题（必须修复后重新审查）

### 严重度定义

| 判定 | 严重度 | 含义 | 动作 |
|------|--------|------|------|
| ❌ | 阻塞 | 代码有明确错误或设计决策被推翻 | 必须修复，阻断后续流程 |
| ⚠️ | 非阻塞 | 存在风险但未达到否决门槛 | 建议改进，不阻断 |
| ✅ | — | 合规 | 无需动作 |

## 沉淀协议：写入 BACKLOG

审查完成后，若有 ⚠️ 或 ❌ 级发现，用 CLI flag 模式调用 `sink-to-backlog.py`。

```bash
python3 scripts/sink-to-backlog.py \
  --source feynman \
  --severity ERROR \
  --summary "违反 P1：假设未验证就当事实用" \
  --detail "具体位置和表现" \
  --fix-hint "修复建议" \
  --context "审查对象简述"
```

严重度映射：❌ → ERROR，⚠️ → WARNING，✅ → 不沉淀。
